# Rift DS

An open source, AI-ready React design system where every visual decision is a token: colour, spacing, radius, and typography are defined once and referenced everywhere, so a change to a single value propagates through the whole system, and a few primitive overrides are a complete rebrand. Built with Vite and TypeScript, explored here in Storybook, and documented in full on the <a href={SITE_URL}>docs site</a>.

## Install

Everything on this page ships as a package. Install it, import the token stylesheet once, and use the components:

```bash
npm install rift-ds
```

```tsx
import 'rift-ds/tokens/tokens.css';
import { Button, Card, Badge } from 'rift-ds';
```

The stylesheet carries the primitives, the semantic tokens, and both themes: import it once at your app root. Deep imports work too (`rift-ds/components/Button/Button`), and the recharts-backed charts live behind a separate `/charts` entry so the optional `recharts` peer is only needed if you use them (the dependency-free chart pieces export from the main barrel with everything else).

The full install and theming guide lives at <a href={`${SITE_URL}/docs/get-started`}>{`${SITE_URL.replace("https://", "")}/docs/get-started`}</a>, with two more ways in beside the package: pull single components as source through the shadcn CLI, or clone the repo outright. Coding agents can read the same reference over MCP: point any Model Context Protocol client at <code>{`${SITE_URL}/api/mcp`}</code> for the component list, prop contracts, and tokens.

## Principles

<div className="ds-principles">
  <div className="ds-principle">
    <h4>Tokens, not hardcoded values</h4>
    <p>Components reference named tokens rather than raw hex or pixel values. Every visual property traces back to a token with a clear, documented purpose.</p>
  </div>
  <div className="ds-principle">
    <h4>Semantic, not literal</h4>
    <p>A component knows it renders a primary action or a small gap, never one specific hue or pixel value. Swapping the primitives underneath re-themes everything without touching component code.</p>
  </div>
  <div className="ds-principle">
    <h4>Composition over configuration</h4>
    <p>Small, focused components that combine freely. A table cell accepts any React node (text, icons, buttons, inputs) rather than a fixed set of props.</p>
  </div>
  <div className="ds-principle">
    <h4>Two sizes, deliberately</h4>
    <p>Every component ships a default and a compact variant. Keeping the size scale small keeps the system consistent and predictable to work with.</p>
  </div>
</div>

</div>

## Architecture

The system flows in one direction: raw values become purposeful tokens, tokens drive components, and components build pages.

<div className="ds-layers">
  <div className="ds-layer">
    <div className="ds-layer-label">Primitives</div>
    <p>The raw scale (colours, spacing, border widths, radii) as fixed hex and pixel values. The source of truth, never referenced directly by components.</p>
  </div>
  <div className="ds-layer-connector" />
  <div className="ds-layer">
    <div className="ds-layer-label">Semantic tokens</div>
    <p>Purpose-driven mappings over the primitives. A primitive becomes "action primary background" or "text secondary". Light and dark are two mappings over the same underlying scale.</p>
  </div>
  <div className="ds-layer-connector" />
  <div className="ds-layer">
    <div className="ds-layer-label">Components</div>
    <p>React components that consume semantic tokens through CSS custom properties. Theme-aware by default: token references rather than conditional logic.</p>
  </div>
  <div className="ds-layer-connector" />
  <div className="ds-layer">
    <div className="ds-layer-label">Application</div>
    <p>The documentation site imports the tokens once and uses the components directly. One data attribute on the root element switches light and dark; a second applies a complete shipped theme.</p>
  </div>
</div>

</div>

## Theming

Light and dark are two readings of the same token layer, not separate systems. Components reference semantic tokens and stay agnostic to the active theme; the theme decides what each token resolves to. Beyond the two modes, {THEME_SELECTOR_ORDER.filter((id) => id !== BASE_THEME_ID).length} complete looks ship in the package as generated stylesheets, each applied by one <code>data-brand</code> attribute. The Theme control in this Storybook's toolbar switches between them, and it opens on Smoke, the served default.

<div className="ds-theme-grid">
  <div className="ds-theme-card ds-theme-light">
    <h4>Light</h4>
    <p>A neutral page floor with containers that contrast against it, near-black text, and one action colour. Contrast between the steps carries most of the depth; shadows are reserved for floating surfaces.</p>
  </div>
  <div className="ds-theme-card ds-theme-dark">
    <h4>Dark</h4>
    <p>Same token names, different primitives. Surfaces darken, text lightens, and the action colour takes its own dark-mode pairing of fill and label, held to the same contrast.</p>
  </div>
</div>

The passive (ghost) action tokens use semi-transparent values, so tertiary controls layer naturally over any surface; primary action fills are opaque by design.

## Conventions

<div className="ds-conventions">
  <div className="ds-convention">
    <strong>BEM naming</strong>
    <span>{"Block__element--modifier with a ds- prefix. .ds-button, .ds-button__icon, .ds-button--compact."}</span>
  </div>
  <div className="ds-convention">
    <strong>Size variants</strong>
    <span>Default and compact. Default uses paragraph tokens (16px), compact uses paragraph-sm (14px) with tighter padding.</span>
  </div>
  <div className="ds-convention">
    <strong>Icons</strong>
    <span>Material Symbols Rounded at 24px default, 20px compact. Custom SVGs where font metrics cause alignment issues.</span>
  </div>
  <div className="ds-convention">
    <strong>Typography scale</strong>
    <span>Mega and display for marketing, heading 1–3 and sub-display for structure, title-body and paragraph tiers for content. Each step is a full token set: family, size, weight, line-height, and letter-spacing.</span>
  </div>
  <div className="ds-convention">
    <strong>Fonts</strong>
    <span>One primary type family and one icon font, with heading and body roles you can split: every theme brings its own faces, and the base theme resolves to Nunito Sans. Complete theme presets ship in the package as stylesheets, applied by one data-brand attribute.</span>
  </div>
